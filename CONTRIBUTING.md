# Aportar a MonotributoDev

Usá un formulario en Issues para compartir una experiencia, solicitar información, corregir contenido o reportar un error. Incluí banco/plataforma, ruta, fecha, canal de atención y fuentes públicas. Diferenciá lo que te ocurrió de lo que exige una norma.

No publiques claves, CUIT personal, CBU, cuenta, documentos de identidad ni extractos sin anonimizar. No inventes ejemplos que parezcan casos reales. Las puntuaciones van en Comunidad, dentro del sitio, y pasan por moderación.

Para proponer cambios de código o datos, abrí una PR con el motivo y cómo lo comprobaste. Ejecutá `npm test` y `npm run build`. Conservá IDs de entidades, referencias a fuentes y fecha. No marques una ruta como documentada sin evidencia de sus tramos. Una transferencia local no se presenta automáticamente como ingreso por MLC.

Las fichas sin información son una invitación a investigar: no reemplaces un pendiente con una suposición. Para reglas tributarias o cambiarias, priorizá documentación oficial y explicitá el alcance del caso.

## Catálogos y provincias

Los datos se editan como JSON con sangría, sin minimizar. Cada provincia tiene su archivo; [estructura e instrucciones](docs/catalogs.md). Adjuntá enlaces oficiales y explicá el alcance de la corrección. El contenido puede tener errores o quedar desactualizado: un aporte verificable mejora la calidad para todos. Cada trámite del sitio permite aportar con el contexto de provincia y sección.
